🔒 Araç çıktıları düz metinden daha hassas — teşhis bloğu araç adı bile taşımaz

Neden bu tür ayrı bir mesele. Kod bloğunu kaybedersen modelden yeniden istersin. Araç çıktısını kaybedersen aracı yeniden çalıştırman gerekir: kota, zaman, bazen para — ve veri o arada değiştiyse aynı sonuç bir daha gelmez.

Aynı araç 5 kez çağrıldıysa 5 öğe. Sıra numarası tek çağrıda bile ekleniyor: ikinci çağrı gelince yeniden numaralamak, geçmişteki kaydı geçersiz kılardı.

Sağlayıcı şeridi kademeyi söylüyor. API kademesi yoksa araç çıktısı ⚠ kırpılmış olabilir işaretli gelir — arayüz sonuçları varsayılan olarak katlıyor ve kırpıyor.

DOM burada en çok yalan söylüyor

GA4 anomalilerine bakayım.
🔧 search_events 214 sonuç · ilk 10 gösteriliyor ▾
Üç anomali öne çıkıyor: 12 Eylül'de organik trafikte %38 düşüş…

Arayüzün gösterdiği: 10 satır. Gerçek sonuç: 214. Katlanmış, kırpılmış, sanallaştırılmış — §12.1'deki bütün DOM tuzakları aynı anda burada.

API kademesi bu yüzden zorunlu gibi. content[] içindeki tool_result bloğu yapısal geliyor; sınır veriden değil şemadan. Araç çıktısı desteği API varsa tam, yoksa kısmi.

Çağrı, sonucun yarısı

{ "_call": { "tool": "search_events", "params": { "period": "30d", "metric": "sessions" }, "at": "2026-09-09T14:22:10+03:00" }, "result": [ … 214 kayıt … ] }

Altı ay sonra elinde 214 satırlık bir JSON var ve hangi tarih aralığıyla çekildiğini bilmiyorsan, o dosya veri değil gürültü. Sonucu saklamanın sebebi genelde onu üretebilmek.

JSON'a yorum konamıyor → sarmalama tek temiz yol. result anahtarı sabit, otomasyonla ayrıştırmak kolay kalıyor. CSV'de # yorum satırı, Markdown'da front-matter.

Kapatılabilir, varsayılan açık. Bağlamsız sonuç dosyası, altı ay sonra silinen dosyadır.
