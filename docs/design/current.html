One visible action per row. Only ↓ is permanent; copy, versions and transfer appear on hover (§8.0 rule 3). Four buttons per row would turn a 47-item list into a wall of controls — the focused row here shows what hover reveals.

Version drift is persistent when history is on. took v3 · this is v5 comes from comparing hashes. Downloading the same file twice is harmless; mistaking a different version for the same one is a real error.

Settings are not a tab. A popup is for doing work; configuration lives on the options page. History appears as a tab only because it is on — with it off there is no tab at all.

The badge counts documents only. Two code blocks and two tool outputs here produce no badge number, and that is correct — they are reached on demand and produce no uninvited signal.

The control names the file it will produce. The name comes from a four-step heuristic chain; without showing it, the user hunts the downloads folder for something called code-7.txt.

Nothing is inserted into the provider's DOM here. One floating control, bound by event delegation and aligned to the hovered block, living in a shadow root on body. On touch devices, where there is no hover, each block gets a small permanent control instead.

The version menu says what changed. +180 −164 against +12 −3 is the difference between "rewritten" and "corrected", and it is the only real input to the choice the user is making. Multiset difference over lines, not set difference — a file is full of repeated } and blank lines, and a set would report a 40-line deletion as −3.
